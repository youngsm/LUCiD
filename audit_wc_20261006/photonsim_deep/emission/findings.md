# PhotonSim optical creation and output lifecycle

Baseline: pinned PhotonSim v1.0.2, commit `9232a7d`, with Geant4 11.3.0.
The source is retained in `../../photonsim_physics/upstream/`. All builds,
scientific imports, event generation, and numerical checks ran in milano CPU
allocations. No production source was modified and no GPU was used.

No new photon-loss, kinematic-rewind, chunking or event-reset defect was found
in the executed water-production cases. The previously established emitting
segment attribution defect remains; the creation-time observer also rules out
first-step timestamp subtraction as its cause.

## Independent creation observer

[AuditEmission.hh](AuditEmission.hh) observes each optical track in
`StackingAction::ClassifyNewTrack`, before its first transport step. It captures
the actual creation position, momentum direction, global time, energy-derived
wavelength, polarization, parent ID and creator process. A second observer at
the optical first-step recording point checks the exact payload PhotonSim
passes to `AddOpticalPhoton`. It consumes no random numbers and changes no G4
track state.

The final comparison checks every raw ROOT value against the observer payload,
then exercises LUCiD's real `_read_photons_for_event` reader. Each created
optical track must occur exactly once in the output; event counts, chunk IDs,
parent registration and ROOT array lengths must agree.

## Executed results

There were 2,131,134 unique source-photon histories, each executed with both
streaming and buffered output, giving 4,262,268 checked photon records across
38 events. All photons were generated by Cerenkov in these water cases.

| Source | Events per output mode | Photons per mode | Streaming chunks | Buffered chunks |
| --- | --- | --- | --- | --- |
| 100 MeV electron | 3 | 65,423 | 3 | 3 |
| 1 GeV negative muon | 2 | 432,577 | 6 | 2 |
| 1 GeV positive pion | 3 | 267,967 | 4 | 3 |
| 2 MeV positron | 3 | 923 | 3 | 3 |
| 2.2 MeV gamma | 3 | 460 | 3 | 3 |
| 10 keV electron (dark control) | 2 | 0 | 0 | 0 |
| Exact GeV/01 production particle bomb | 3 | 1,363,784 | 15 | 3 |

The mixed production event with the largest output emitted 1,072,761 photons,
exercising ten full 100,000-photon chunks plus a remainder. For every case:

- Creation count, first-step recording count and ROOT metadata count agree;
  there are no unrecorded creations or duplicate optical classifications.
- Creation positions, directions and wavelengths match the first-step record
  exactly in double precision. The largest emission-time difference is
  `1.819e-12 ns`, from subtraction after the first flight.
- Every first optical step ended in `OpAbsorption`, yet every created photon
  was retained. PhotonSim's 35 m optical absorption affects this throwaway G4
  flight, not the emitted-photon yield subsequently transported in LUCiD.
- ROOT values exactly equal the float32 cast of the complete record payload.
  LUCiD's position conversion from mm to m and unmodified ns/nm/direction
  handoff agree independently with those values.
- Streaming and buffered photon arrays are bitwise identical per event,
  including all event boundaries and zero-light events.
- Every emitting parent and every nonprimary track's parent appears in the
  track registry. Every assigned segment belongs to the photon's actual
  parent track. This includes 17 pion deflection children in the pion sample
  and three in the production bomb sample, per output mode.

The observer's output is also bitwise identical to the pre-existing, unchanged
v1.0.2 baseline files for eleven electron, muon, pion and gamma events. This
checks that the instrumentation and optional process-name storage did not
change the source histories.

## Code-grounded lifecycle coverage

- `SteppingAction.cc:87-105` registers non-optical tracks on their first step
  using their vertex position, vertex direction and vertex kinetic energy.
- `SteppingAction.cc:192-216` records optical vertex position/direction,
  reconstructed creation time and wavelength on step one. The independent
  pre-transport observer verifies those data in the tested material.
- `StackingAction.cc:45-50` applies the accepted 10 microsecond creation cut
  to non-optical particles and classifies optical photons as urgent. No
  additional optical-photon selection or efficiency thinning appears here.
- `DataManager.cc:544-572` stores all individual photons when the production
  `storeIndividual` flag is true, increments the event-wide counter and
  flushes full chunks. `EndEvent` drains the final partial chunk and uses that
  event-wide counter rather than the cleared buffer size.
- `DataManager.cc:298-313` resets event buffers and counters before each event.
  Differing photon multiplicities exercise the resets; separate zero-light
  events exercise the empty-output branch.
- `PhotonSim.cc:81` explicitly constructs a serial run manager. The global
  DataManager singleton is therefore not exposed to a multithread race on
  the selected production path. A hypothetical MT build is not certified.
- The production bomb test uses `generate_macro` on the unchanged
  `lucid/production/configs/GeV/01_pbomb.json`, retaining its species, energies,
  multiplicity, isotropic directions and decay settings. Only event count,
  output path, deterministic seed and output-observation flags are supplied.

The active water material provides Cerenkov emission and no scintillation/WLS
emission spectrum. No non-Cerenkov optical origin was observed. This does not
certify PhotonSim's other materials, whose emitted process mixture and optical
re-emission would require separate checks.

## Attribution diagnosis

The first-step time rewind is not responsible for the known segment-truth
defect. Replacing each recorded photon time with the exact pre-transport birth
time changes zero segment assignments in the eleven baseline-control events.
For example, the first 2.2 MeV gamma event still has segment photon-count L1
error 8 among 144 photons; the second 1 GeV muon event still has L1 error 418
among 217,190 photons. The numerical time differences are far too small to
explain these cases.

An exact parent-step tag prototype is exercised by
[run_step_tag.sbatch](run_step_tag.sbatch),
[EmissionStepInfo.hh](EmissionStepInfo.hh), and
[analyze_step_tag.py](analyze_step_tag.py). Milano job `39971599` completed
successfully, with [results](step_tag_results.json) and
[log](step-tag-39971599.log). The observer tags each optical secondary while
the actual emitting parent's step is executing, so it does not infer the
parent step from times or geometry.

Across eleven gamma, electron, pion and muon events, **1,206 of 766,427 photons
have the wrong step in the original output**. The direct tag fixes all 1,206;
the corrected step counts exactly equal `Segment_NCherenkov` in every event.
The original and corrected photon position, direction, wavelength and time
arrays are bitwise identical.

Every incorrectly assigned photon already has a Geant4 birth timestamp later
than its actual emitting step's end time. The largest excess is
`0.000561723 ns`. The time search consequently assigns these photons to one,
two or three later steps of the same parent. The photon times remain negligible
compared with detector timing resolution, but they cannot be used to infer
the exact emitting-step identity. This provides a causal explanation for the
known truth defect, not evidence of a large optical-yield error.

The [isolated correction diff](step_tag_prototype.diff) carries the parent's
`GetCurrentStepNumber()-1` on optical secondaries using `G4VUserTrackInformation`,
retains that index alongside each stored photon, then calculates the global
segment index as `trackSegmentBaseOffset[parentID] + emissionStepIndex`.
Production should preserve any existing user track information if that API
is used elsewhere; the pinned code has none. The audit-only A/B environment
switch and binary observer need not be included in a production fix.

A minimal regression for the existing gamma fixture is:

```python
import numpy as np
import uproot

tree = uproot.open("gamma_tag_baseline.root")["OpticalPhotons"]
a = tree.arrays(["Photon_SegmentIndex", "Segment_NCherenkov"], library="np")
expected = a["Segment_NCherenkov"][0]
actual = np.bincount(a["Photon_SegmentIndex"][0], minlength=len(expected))
np.testing.assert_array_equal(actual, expected)
```

This assertion fails on the original first event (144 photons; four wrong
assignments; count L1 error eight) and passes on `gamma_tag_fixed.root`.
The full executed analysis additionally checks the exact per-photon tag,
because comparing counts alone can miss errors that cancel within a bin.

These checks establish conservation and provenance for the sampled source
histories. They do not independently validate every Geant4 interaction cross
section, polarization/decay process, material dispersion curve, or particle
energy. Those are separate physical-model audit lanes.
