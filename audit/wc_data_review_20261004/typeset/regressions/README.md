# LUCiD WC DATA physical regressions

These 11 tests assert correct behavior and intentionally fail against the audited implementation.
Seven call current Python production functions; four inspect output newly generated by a candidate PhotonSim executable.
The source-output tests skip unless `PHOTONSIM_OUTPUT_DIR` is set.

## Copy into another checkout

Copy `conftest.py`, `test_runtime.py`, `test_photonsim_outputs.py`, and `prepare_photonsim_inputs.py` together under any test directory in a LUCiD checkout.
The fixture discovers the checkout from its ancestors; set `LUCID_REPO` if the tests are elsewhere.
The checkout must include the SK_WAND configurations and their referenced geometry and QE data.
Use the checkout's Python dependencies from `pyproject.toml`, plus `pytest>=7`; the source tests also need `uproot>=5` and NumPy.
The recorded runs used Python 3.12, JAX 0.11.0, Flax 0.12.8, and NumPy 2.4.3.
No SIREN inference, ROOT C++ installation, or GPU is required for the seven runtime tests.

Run all commands after entering an allocation:

```bash
srun --partition=milano --account=neutrino:ml-dev@milano --qos=preemptable \
  --ntasks=1 --cpus-per-task=2 --mem=8G --time=00:30:00 --pty bash
cd /path/to/LUCiD
export JAX_PLATFORMS=cpu OMP_NUM_THREADS=1 OPENBLAS_NUM_THREADS=1 MKL_NUM_THREADS=1
export PYTHONPATH="$PWD"
export XLA_FLAGS='--xla_cpu_multi_thread_eigen=false intra_op_parallelism_threads=1'
# Select an existing environment with the project dependencies and pytest.
export LUCID_PYTHON=/path/to/environment/bin/python
uv run --no-project --python "$LUCID_PYTHON" python -m pytest -q \
  path/to/regressions/test_runtime.py
```

The physical assertions require no changes after fixing production code.
Do not use `--isolated-fixes` to assess a developer's production fix: that option bypasses production functions with audit-owned corrected copies.
It exists solely to reproduce the audit's correction checks.
It neither applies patches to the checkout nor marks tests as expected failures.

The individual unified diffs under `patches/` have repository-relative paths.

The timing correction is verified for the selected `ski` digitizer.
The negative-TTS test concerns the dormant realistic hit mode, not the selected per-segment/TTS-zero production path.

## Regenerate source outputs after every C++ change

Rebuild the candidate PhotonSim executable using its supported Geant4/ROOT environment.
Point `PHOTONSIM_BIN` to that newly built executable; using old ROOT files cannot validate a source change.
The helper below writes portable macros and a genuine GENIE `gRooTracker` input.
It does not reuse audit-lane assertions or a bundled output fixture.

```bash
export REGRESSIONS="$PWD/path/to/regressions"
export PHOTONSIM_BIN=/path/to/newly/built/PhotonSim
uv run --no-project --python "$LUCID_PYTHON" python \
  "$REGRESSIONS/prepare_photonsim_inputs.py" "$REGRESSIONS/candidate_outputs"
export PHOTONSIM_OUTPUT_DIR="$REGRESSIONS/candidate_outputs"
for case in gamma_prompt gamma_delayed pion_deflection genie_isotropic thermal_neutron; do
  "$PHOTONSIM_BIN" "$PHOTONSIM_OUTPUT_DIR/$case.mac" \
    > "$PHOTONSIM_OUTPUT_DIR/$case.log" 2>&1
done
export PHOTONSIM_THERMAL_ROOT=thermal_neutron.root
unset PHOTONSIM_TEST_SUFFIX
uv run --no-project --python "$LUCID_PYTHON" python -m pytest -q \
  "$REGRESSIONS/test_photonsim_outputs.py"
```

The thermal baseline in the recorded audit had the 10 microsecond source cutoff removed to isolate the elastic-physics defect.
Otherwise the source cutoff also destroys this sample before capture, which remains a valid failure but does not isolate the capture-time model.
The mean-clock oracle uses water density 1 g/cm3, two hydrogen atoms per water molecule, thermal speed 2200 m/s, and hydrogen capture cross section 0.3326 barn.
The tail requirement rejects the excessive late-capture distribution separately from the mean test.
